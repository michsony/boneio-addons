# boneio-addons

Reusable ESPHome additions for BoneIO Studio.

## Repository layout

- `components/boneio_irrigation/`: irrigation scheduler, native ESPHome entity templates and build-time generation.
- `examples/`: installation YAML examples.
- `packages/`: shared YAML packages for future additions.

## Irrigation

Export the installation YAML from BoneIO Studio and use it in ESPHome Builder.
The YAML contains the configured zones, physical output references, pumps,
sensors, programs, start slots, capacities and initial settings. Fixed logic is
loaded from this repository during compilation:

```yaml
external_components:
  - source:
      type: git
      url: https://github.com/michsony/boneio-addons
      ref: v0.1.0
    components: [boneio_irrigation]
    refresh: never
```

The `boneio_irrigation` section is installation data generated by Studio. It
expands into native ESPHome components during validation and code generation;
the expanded definitions are never written back to your YAML. Do not add a
second set of template entities or duplicate physical GPIO definitions.

The controller uses native ESPHome `sprinkler` executors for valves and pumps.
The portable scheduler adds local programs, queueing, Cycle & Soak, safety
checks, deduplication and persistent settings. Home Assistant parameters remain
writable without recompilation. Runtime operation does not contact GitHub or
BoneIO Studio. Initial firmware builds need access to the pinned Git revision.

Entity IDs are compatible with the previous expanded Studio generator. Your
Home Assistant entity registry may have renamed entities; existing Studio
dashboard mappings should be retained.

Keep `api.reboot_timeout` and the configured network component's
`reboot_timeout` at `0s` to prevent connectivity failures from rebooting an
autonomous watering controller. Studio exports these settings.

Tested with ESPHome **2026.9.1**, ESP32 with ESP-IDF. The component uses native
ESPHome validation and code generation APIs; verify a firmware build before
upgrading ESPHome. Software checks do not replace hydraulic commissioning or
testing your physical valves, pumps and emergency-stop wiring.

## Releases and credentials

Use a release tag or commit in `ref`, rather than a floating branch. Never
commit Wi-Fi passwords, API keys, device secrets or real customer installation
files. The public component contains no installation credentials.
